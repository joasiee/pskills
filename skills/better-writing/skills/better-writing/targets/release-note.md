# Release-note text

Text that ends up in the release notes, such as a customer impact field on a work item. A customer reads it, not a colleague.

When another skill or a template owns this text (when to fill it, the template, the content rules), follow it. Where it differs from the baseline, it wins. These rules apply either way:

- No code names, PR numbers, branch names, or customer names. The baseline rule "use the codebase's names" does not apply here.
- Address the reader as "you" and describe what they see, not the mechanism.
- A semicolon is allowed where a template uses one ("Fixed an issue where ...; ...").

The rest of the baseline still applies: voice, plain English, truth, and the cut list. The "Not technical" and "How much to share" rules in `customer-message.md` apply too.
